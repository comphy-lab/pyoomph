Custom functions with multiple return values
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The aforementioned :py:class:`~pyoomph.expressions.cb.CustomMathExpression` can only return a single scalar value at each time. Sometimes, however, you want to obtain more than one return value. Of course, one could implement one :py:class:`~pyoomph.expressions.cb.CustomMathExpression` for each of these values, but a lot of computations might be the same for each of these values. In this case, it is beneficial to use another class to obtain multiple values at once, namely the ``CustomMultiReturnExpression``. This is not explained in detail here, but we refer to the code in :py:mod:`pyoomph.expressions.tensor_funcs`.

Besides the values themselves, such a function must supply their derivatives with respect to its arguments, since pyoomph needs them to assemble the Jacobian. You fill the ``derivative_matrix`` in ``eval`` whenever the ``flag`` argument is set, and the corresponding ``derivative_matrix`` in your ``generate_c_code``. If you do not want to work them out, the macro ``FILL_MULTI_RET_JACOBIAN_BY_FD`` at the end of your C code fills them by finite differences instead.

If you want to use the function in a stability analysis or in bifurcation tracking, i.e. with ``setup_for_stability_analysis(analytic_hessian=True)``, pyoomph also needs the *second* derivatives, since a Hessian differentiates the residual twice. You do not have to do anything for this to work: the generated code will finite-difference your Jacobian. You can do better by implementing ``eval_second_derivatives`` (filling ``second_derivative_tensor[i, j, k]``, which must be symmetric in ``j`` and ``k``) and ``generate_c_code_second_derivatives``, or -- if your ``eval`` uses nothing but arithmetic and ``numpy`` functions -- simply by setting ``self.second_derivative_mode = "ad"`` in your constructor, which obtains the exact derivatives by running your own ``eval`` on dual numbers.

One caveat is worth knowing: if your *Jacobian* is itself filled by finite differences, then finite-differencing it again leaves no accuracy at all. For anything that will appear in a Hessian, supply a real Jacobian.
